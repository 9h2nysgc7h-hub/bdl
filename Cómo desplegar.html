Cómo desplegar la plataforma

Plataforma BDL · gratis de punta a punta

Mismo stack que ya usás en el CRM de Nave: Supabase (login + base de datos) + YouTube no listado (video) + Vercel (hosting). Los tres son gratis para este volumen de alumnos — no hay ningún paso pago acá.

1 · Crear el proyecto en Supabase

supabase.com → New project (plan gratis). Guardá la contraseña de la base que te pide, no hace falta para esto pero por las dudas.

2 · Cargar la base de datos

SQL Editor → New query → pegá todo el contenido de schema.sql → Run.
Después, otra query nueva → pegá todo el contenido de seed.sql → Run. Esto carga los 11 módulos y las 83 lecciones reales, sin video todavía.

3 · Activar registro sin confirmación por mail

Cualquiera puede crear su cuenta solo, desde el botón "Crear cuenta" del login — por eso conviene sacarle la confirmación por mail para que no se trabe en ese paso. Authentication → Providers → Email → apagá "Confirm email". Igual nadie entra a ver contenido hasta que vos (o un admin) lo apruebes desde el panel — la confirmación por mail no es el filtro real, la aprobación sí.

4 · Conectar el archivo con tu proyecto

Project Settings → API → copiá Project URL y anon public key. Abrí index.html, buscá las líneas SUPABASE_URL y SUPABASE_ANON_KEY cerca del principio del <script>, y pegalos ahí.

5 · Crear tu propio acceso como founder

Authentication → Users → Add user → tu email + una contraseña, con "Auto Confirm User" tildado.
Después, en SQL Editor, correr (reemplazando el email):
update profiles set rol='founder' where id = (select id from auth.users where email='tu-email@gmail.com');
Con eso ves el panel Admin al entrar.

6 · Subir a Vercel

Mismo flujo que ya conocés del CRM: creás el proyecto en Vercel y subís la carpeta Plataforma BDL (con el index.html ya configurado). Te da una URL tipo bdl-plataforma.vercel.app.

7 · Los alumnos se registran solos — vos los aprobás

Cada alumno entra a tu URL, click en "¿No tenés cuenta? Creala", pone su nombre y apellido, email y contraseña. Queda en una pantalla de "pendiente de aprobación" hasta que entrás a Admin → Miembros pendientes de aprobación y le das Aprobar. Recién ahí puede ver el contenido, arrancando en Semana 0.
Si preferís seguir creando vos los accesos a mano en algún caso puntual, podés — Authentication → Add user (con "Auto Confirm User" tildado) y después aprobarlo igual desde Miembros, porque arranca sin aprobar por default.

8 · Cargar cada video a medida que lo grabás

Subís el video a YouTube como No listado (no público, no aparece en búsquedas — solo entra quien tiene el link). Copiás el ID de la URL: en youtube.com/watch?v=dQw4w9WgXcQ el ID es dQw4w9WgXcQ. Entrás a la plataforma logueado como founder → Admin → pegás el ID en la fila de esa lección → Guardar. Aparece al toque para todos los alumnos que ya tengan ese módulo desbloqueado.
El trade-off real de que sea gratis: "no listado" en YouTube no es lo mismo que privado — nadie lo encuentra buscando, pero si un alumno copia el link y se lo pasa a alguien de afuera, esa persona sí puede verlo. Para un programa de $2.000 con pocos alumnos por camada, es un riesgo bajo y es el mismo trade-off que acepta la enorme mayoría de cursos chicos. Si en algún momento esto crece y te preocupa de verdad, el salto siguiente es un hosting de video pago con protección real (Vimeo privado o Cloudflare Stream) — no hace falta ahora.

Desbloqueo semanal — es manual, lo hacés vos

Cada alumno arranca viendo solo la Semana 0. Cuando termina una semana y su entregable, toca "Avisar que terminé" dentro de la plataforma — vos ves ese pedido apenas entrás a Admin, en la sección "Pedidos de desbloqueo", con un botón para desbloquearle la semana siguiente. También podés adelantar o corregir la semana de cualquiera a mano, sin esperar su pedido, desde la tabla de Alumnos en el mismo panel.

Roles: founder y admin

Además de vos (founder), podés darle el panel Admin a alguien más — en Miembros, en la fila de esa persona, cambiale el rol a admin y Guardar. Puede aprobar miembros, desbloquear semanas y cargar videos igual que vos.

Duración real de los videos (opcional, gratis)

console.cloud.google.com → creá un proyecto (o usá uno que ya tengas) → APIs y servicios → Biblioteca → buscá "YouTube Data API v3" → Habilitar.
APIs y servicios → Credenciales → Crear credenciales → Clave de API. Te da una clave para copiar.
Recomendado, para que nadie más la use: en esa misma clave, click en editarla → Restricciones de API → marcá solo "YouTube Data API v3". Opcional además: Restricciones de aplicación → Referentes HTTP → agregá tu dominio de Vercel.
Pegá la clave en index.html, en la línea YOUTUBE_API_KEY (al lado de las de Supabase).

Con esto, cada vez que guardás un YouTube ID en Admin, la duración se sincroniza sola con la real del video — ya no con la estimación del guion. También hay un botón "Sincronizar todas las duraciones" para corregir de una los videos que ya habías cargado antes de este paso. Es gratis: la cuota diaria gratuita de Google alcanza de sobra para esto (una consulta por video, no por cada vez que alguien lo mira).

Recursos por lección

Debajo de cada video podés dejar el entregable, un link a un documento o lo que haga falta. Se carga desde Admin → Recursos por lección — elegís la lección, le ponés un título y, si aplica, un link (el link es opcional: sin él queda como una nota de texto suelta). Aparece al toque para quien tenga esa semana desbloqueada.

Si ya tenías el proyecto armado antes de estos cambios

Corré, en este orden, en el SQL Editor (una sola vez cada uno):
1. migracion-desbloqueo-manual.sql — agrega el desbloqueo manual por semana.
2. migracion-registro-aprobacion.sql — agrega el registro público y la aprobación de miembros.
3. migracion-recursos.sql — agrega los recursos por lección.
Ninguno toca lo que ya tenés cargado, y no hace falta volver a correr seed.sql.
